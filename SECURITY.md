# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a security problem.

Use GitHub's private reporting instead:
[**Report a vulnerability**](https://github.com/ZENSH1/ExpenseTracker/security/advisories/new).
It opens a private thread visible only to the maintainer, and it lets a fix and an
advisory be prepared before anything becomes public.

Expect an acknowledgement within a few days. If you have not heard back within two
weeks, feel free to open a public issue that says only that you are waiting on a
security response — no details.

## Supported versions

This is a pre-1.0 project shipped to Play internal testing. Only the most recent
release on the `internal` track receives fixes; older tags are not patched.

## Scope

In scope:

- The Android app in `app/`
- The Firestore security rules in `firestore.rules`
- The release pipeline in `.github/workflows/`

Out of scope:

- Findings that require a rooted or physically compromised device
- The Google OAuth **client ID**. It is a public identifier by design, ships inside
  every APK, and is not a credential.
- Reports generated by an automated scanner with no demonstrated impact

## What this app holds

Expense records — trackers, sources and receipts — stored locally in Room and synced
to Cloud Firestore per signed-in user. Access is granted by membership of a tracker's
`sharedWith` array; see the comments in `firestore.rules` for the model. The ledger is
excluded from Google cloud backup (`app/src/main/res/xml/data_extraction_rules.xml`).
